# Reach perception: hand pointer and pinch selection (EXPERIMENTAL)

Hands come from `finger_processing/` at the repo root, the single camera + MediaPipe HandLandmarker pipeline (Tasks
API, VIDEO mode, up to two hands). This worker consumes its stream: the primary hand (`hands.primary` in
`finger_processing/config.yaml`, left by default) moves a Reach pointer with the index fingertip, and a pinch-drag
becomes a screen-region selection. Its own uv project; nothing here is added to `backend/`.

## Setup
```
cd perception
uv sync                                   # Python 3.12; installs ../finger_processing (editable), mediapipe 1.2.3
curl -L -o ../finger_processing/hand_landmarker.task \
  https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/latest/hand_landmarker.task
```
The model URL is the "HandLandmarker (full)" bundle from Google's MediaPipe hand landmarker docs. It lives in
`finger_processing/` (gitignored) and is shared by everything that reads hands.

## Run
```
uv run python -m reach_perception.worker --selftest       # synthetic landmark fixtures, no camera, no keys
uv run python -m reach_perception.worker --camera-check   # opens the camera 3 s: frame size, fps, hands, latency
uv run python -m reach_perception.worker                  # preview window; q quit, c calibrate, r reset mapping
uv run pytest -q                                          # camera-free, key-free
```
If the backend is running (`reach serve`), the worker reads `$REACH_DIR/run/server.json` and `run/token`
(default `<repo>/.reach`; from a git worktree with no server of its own it falls back to the main checkout's
`.reach`, and captures go to the same `.reach/captures/` so the server accepts their path). Its hello says
`role: "perception"`. Without a server it runs local-only.

`--selftest --bridge` replays the synthetic `clean_pinch` fixture to a running server: one `pointer` per frame and one
`select` (synthetic text plus a 2x2 synthetic PNG). No camera, no screen capture, no keys.

## Permissions the owner must grant
- **Camera** for the terminal app that runs the worker (System Settings > Privacy & Security > Camera). Until it is
  granted, `--camera-check` prints a message naming this permission and exits 2. Quit and reopen the terminal after.
- **Screen Recording** for the same terminal, for `screencapture -R` of the selected region. Without it the capture
  holds no window content, OCR reads nothing and the preview says "pointer demo only".

## What is implemented
- `pinch.py` (pure, tested): One-Euro smoothed index-tip pointer, mirrored to match the preview. Pinch ratio =
  thumb-tip to index-tip distance / wrist to middle-MCP distance (pixels). Hysteresis: on below 0.25 held 150 ms, off
  above 0.40 held 80 ms. Open palm (four fingers and thumb extended, not pinching) held 400 ms fires one local `pause`
  per episode and suppresses pinch; no model call. Hand missing > 1 s hides the pointer and cancels a drag (no select).
- `screen_map.py` (pure, tested): fixed mapping (camera box 0.15..0.85 stretched to the main display, in points) or a
  4-corner calibration (press `c`, reach to each corner and pinch) solved as a homography and saved to
  `.reach/calibration.json`.
- `worker.py`: camera -> landmarks -> gestures -> bridge. On pinch release: rect in screen points (a tiny drag becomes
  a 480x160 box around the pointer), `screencapture -x -R` to `.reach/captures/selection-<ts>.png`, local OCR with the macOS
  Vision framework (`capture.py`), then `select {selection: {region, text, image_path}}` over the bridge.
- `preview.py`: OpenCV window, mirrored, landmarks, state line, labelled EXPERIMENTAL.
- Camera frames are never written to disk. The only file written per selection is the screen-region PNG.

## Experimental / not done
- Fixtures in `reach_perception/fixtures/` are SYNTHETIC (generated by `synth.py`), not recorded from a hand.
- No pinch accuracy has been measured on a real hand yet (camera permission was not granted when this was built).
- Vision OCR is tested on rendered text (pytest); it has not been checked on a live `screencapture` of a paragraph,
  which also needs Screen Recording permission. One early probe returned empty text and a rerun read it correctly, so
  an empty result is reported as "pointer demo only". `--no-ocr` sends the rect only.
- Bridge: `select` and `pointer {x, y, state: hover|pinch}` are relayed by the server to overlay clients
  (`backend/reach/relay.py`); the select is kept 60 s for the next ask. When the hand is lost nothing is sent and the
  overlay fades its ghost pointer after 1 s. Real-hand use through the overlay is untested.
